## FINDINGS (Potential Vulnerabilities)

### FINDING 1: Unauthenticated Print Job Submission (HIGH)

**Endpoint:** `/print/print.php`
**Impact:** Any unauthenticated user can submit print jobs to the device

The Job Submission page is fully accessible without authentication. It accepts:
- PDF, PostScript, PCL files
- Job types: Normal Print, Secure Print, Save Job for Reprint, Delay Print, Save and Print
- 2-sided printing options
- Job naming

**Attack scenarios:**
1. Resource exhaustion by submitting large/many print jobs
2. Malicious PostScript execution (PS is a Turing-complete language)
3. PostScript-based file read/write on the printer filesystem
4. Information disclosure via PostScript file system access
5. Credential harvesting via PostScript SNMP/network operations
6. Phishing via printing attacker-controlled content

**Reproduction:** Navigate to `https://13.13.1.110/print/print.php` without authentication.

### FINDING 2: Unauthenticated Device Reboot via CSRF (MEDIUM-HIGH)

**Endpoint:** `/dummypost/xerox.set`
**Form data:**
- `_fun_function = HTTP_Machine_Reset_fn`
- `NextPage = /stat/rebooted.php?redir=5`
- `CSRFToken = 629ae92839c85...` (exposed in unauthenticated page source)

The reboot form action, function name, and **CSRF token** are all exposed in the unauthenticated status page HTML. The CSRF token is embedded client-side without requiring authentication, meaning:
1. An attacker can extract the token from the unauthenticated page
2. Submit a POST to `/dummypost/xerox.set` with the reboot function
3. Potentially trigger an unauthenticated device reboot (DoS)

**Note:** Need to verify if the token is session-bound or static. If static, this is a direct unauthenticated reboot.

### FINDING 4: Unauthenticated Remote Control Panel Access (MEDIUM)

**Endpoint:** `/support/remoteUI/RUIHome.php`

The Remote Control Panel page is accessible without authentication. It shows:
- Configuration status (Enabled For Admin Only)
- Access control settings
- "Start Remote Session" button
- Xerox Generic Root Certificate Authority download link

If the "Start Remote Session" button works without auth, this gives full remote access to the printer's physical control panel.

### FINDING 5: CSRF Token Exposure on Unauthenticated Page (MEDIUM)

The main status page (`/stat/welcome.php`) includes a CSRF token in a hidden form field that is served to unauthenticated users:
```
CSRFToken = 629ae92839c85656f53c044fbfa521165cc40e1c7d7a4f43a39403e387a97e811422b34358c9bec850420d6816bd41a7b5e1633e2f95137a7ebf42d77fdeefac
```

This token is associated with the `HTTP_Machine_Reset_fn` function. If this same token pattern is used for other administrative functions (configuration changes, user management), an attacker could:
1. Harvest the token from the unauth page
2. Craft requests to admin-only endpoints using the harvested token

### FINDING 6: Self-Signed TLS Certificate Chain (LOW-MEDIUM)

The device uses a self-signed Xerox Generic Root Certificate Authority. While TLS config best practices are OOS, the self-signed root creates a trust issue:
- Clients must manually trust the Xerox root CA
- Users are trained to accept certificate warnings
- MitM attacks become easier as users ignore cert warnings
- The certificate CN reveals the device hostname and MAC address

### FINDING 7: NTP Communication Error (INFO)

The device reports: "Network Time Protocol (NTP) communication error; machine time may be inaccurate."

This could indicate:
- NTP server misconfiguration
- Network isolation issues
- If time is inaccurate, TLS certificate validation and log timestamps are unreliable

### FINDING 8: Remote Services Connectivity Error (INFO)

"Machine is unable to contact the Xerox Remote Services datacenter."

The device cannot reach Xerox's cloud services, potentially meaning:
- Firmware updates are not being applied
- Security patches may be missing
- Device telemetry is not being monitored
